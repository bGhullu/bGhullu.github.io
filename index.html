Legacy → Lessons → New Architecture

The rebuild was not motivated by taste. It was motivated by a structural analysis of the existing system that found specific, nameable defects — each of which became a named constraint in the new design.

Stage 1

Legacy system

A single-crate Rust monolith that worked, was well tested, and had accumulated real structural debt.

  • One strongly-connected dependency component
  • 40+ distinct dependency cycles
  • Runtime state authority split three ways
  • Three-plus divergent profit calculators
  • Seventeen ad-hoc event channels
Stage 2

Engineering lessons

A forensic pass converted each defect into a permanent, testable constraint rather than a TODO.

  • Layering by directory name is not layering
  • Two simulation paths that disagree is a correctness bug
  • Detection and execution must share one authority
  • An ungated send path is a safety defect, not a feature
  • Test counts prove nothing without invariants
Stage 3

New architecture

The constraints were ratified into an architecture where violations fail to compile or fail CI.

  • Acyclic crate graph, enforced by tripwires
  • One state authority, one writer, immutable generations
  • One sequential profit ledger per candidate
  • One broadcaster; capability withheld until authorized
  • Invariant-named tests that assert architectural truths

Engineering practice

What the artifacts reveal about how this work is done — independent of the domain.

Independent verification

The author of an implementation never certifies it. Each milestone has an independent adversarial gate written by a separate reviewer that re-derives claims from fresh evidence, distrusts the prior conclusion, and must record its own independence caveats.

Evidence labels

Every statement in every report carries a label: FACT, RATIFIED, INFERENCE, RECOMMENDATION, BLOCKER, OPEN DECISION. Speculation is never allowed to masquerade as measurement.

Fail closed by default

Unknown capability ⇒ deny. Missing evidence ⇒ refuse. Stale simulation ⇒ reject. Channel loss ⇒ an explicit policy, never a silent fallback. The safe outcome is the one that happens when something is missing.

Rollback points and scope fences

Every milestone declares its rollback point, acceptance criteria, and blocking conditions before work starts. Out-of-scope items are recorded as deferred — never silently dropped, never quietly widened.

Anti-circular evidence

Where a test could pass by comparing a value against itself derived from the same source, it is restructured: expectations are authored independently of the bytes under test, and any claim that remains single-sourced is named explicitly rather than hidden.

Safety before capability

The rebuild required four pre-entry safety and correctness gates to pass against the legacy tree before any restructuring milestone could begin — including eliminating accidental live-execution paths and re-proving core math from first principles.

Scope & honesty note

What this portfolio does not claim

No claim of profitable live trading. No claim of production deployment. No claim that the re-architecture is finished. Metrics are quoted from written artifacts with their provenance attached; where a number is reported by a review rather than re-executed, the artifact says so and this site repeats that caveat rather than dropping it. Complete algorithms, proprietary heuristics, opportunity-selection logic, execution logic, and infrastructure topology are deliberately not published — this site demonstrates engineering understanding, not reproducibility.
